# معايير الإصدار الرسمي لـ MYFI على Android

## 1. ما المقصود بالإصدار الرسمي؟

الإصدار الرسمي ليس ملف APK للتجربة فقط. المقصود هو:

- تطبيق منشور من خلال Google Play Console.
- ملف `AAB` إنتاجي موقّع، وليس نسخة Debug.
- رقم حزمة ثابت مثل `com.myfi.app`، ورقم إصدار قابل للترقية.
- سياسة خصوصية وبيانات أمان وإفصاحات مكتملة.
- اختبار داخلي ثم اختبار مغلق ثم إطلاق تدريجي.
- خطة للمراقبة والدعم واستعادة الإصدار عند ظهور مشكلة.

## 2. بوابات القبول

لا ننتقل إلى البوابة التالية قبل إغلاق شروطها.

### البوابة A: اكتمال المنتج

- تعمل المسارات الأساسية: إضافة حركة، تعديلها، حذفها، التحويل، الدين، الهدف، الالتزام الشهري، التأجيل، الأرشيف، والاستعادة.
- تظهر رسائل واضحة عند انتهاء الدين أو الهدف.
- لا توجد مشكلة `P0` أو `P1` مفتوحة.
- لا تفقد المزامنة أو الاستعادة أي حركة أو دفعة أو توفير.
- تتطابق أرقام الرئيسية والتقارير والسجل وملف التصدير.
- تعمل العربية والإنجليزية وRTL والوضع الفاتح والداكن.

### البوابة B: جاهزية Android التقنية

- يثبت `applicationId` ولا يتغير بعد أول نشر.
- يثبت اسم التطبيق والأيقونة وشاشة البداية ونسخة التطبيق.
- يبنى ملف `AAB` إنتاجي بواسطة EAS، ويُفحص بعد البناء على جهاز Android حقيقي.
- يستهدف التطبيق API حديثاً مطابقاً لمتطلبات Google Play. ابتداءً من 31 أغسطس 2026 يجب أن تستهدف التطبيقات الجديدة والتحديثات Android 16، أي API 36 أو أعلى.
- لا توجد أسرار أو مفاتيح خدمة أو ملفات `.env` داخل الحزمة أو المستودع.
- الصلاحيات أقل ما يمكن: الكاميرا أو الميكروفون أو الملفات لا تطلب إلا عند الحاجة مع شرح واضح.
- حجم الحزمة ووقت التشغيل والبدء والاستهلاك مقبولة على أجهزة متوسطة.

### البوابة C: التوقيع وسلسلة الثقة

- نستخدم Google Play App Signing.
- مفتاح الرفع منفصل عن مفتاح توقيع التطبيق ومحفوظ خارج Git وفي مكانين آمنين.
- تفعيل التحقق بخطوتين لحساب Play Console.
- حفظ بصمات SHA-256 الخاصة بتوقيع Google لاستخدامها مع Supabase أو OAuth أو أي مزود خارجي.
- لا تُشارك صلاحية مالك Play Console؛ يضاف كل متعاون بحساب منفصل وصلاحيات أقل.

### البوابة D: الخصوصية والأمان المالي

- سياسة خصوصية عربية وإنجليزية داخل التطبيق وعلى رابط HTTPS عام.
- تعبئة Data safety بدقة، بما يشمل Supabase، البريد، الصوت، الصور، التحليلات، والنسخ الاحتياطي إن استُخدمت.
- لا تظهر أرقام المحافظ أو الديون أو الحركات أو بيانات الغرف للعامة.
- تطبيق RLS واختبار عزل المستخدم والغرفة قبل الإصدار.
- عدم وضع `service_role` أو أي مفتاح سري في تطبيق العميل.
- عند إنشاء حساب داخل التطبيق، توفير طلب حذف الحساب والبيانات من داخل التطبيق ومن رابط ويب خارجي.
- تحديد ما يُحذف فوراً وما يُحتفظ به لأسباب قانونية أو أمنية وذكره في سياسة الخصوصية.
- إعلان Financial features في Play Console بدقة؛ MYFI أداة إدارة مالية شخصية، ولا ندعي تقديم قروض أو استثمار أو خدمات مصرفية إن لم تكن موجودة.

### البوابة E: الاختبار والتجربة

- تمرير الأوامر المحلية:

```powershell
npm run test:logic
npm run test:db-schema
npm run test:backfill
npm run test:ui
npm run test:database
npm run verify:android
npm run build:aab
```

- اختبار على جهاز Android حقيقي، وعلى الأقل نسخة Android قديمة مدعومة ونسخة حديثة.
- اختبار التثبيت الجديد والتحديث فوق نسخة سابقة والاستعادة بعد حذف التطبيق.
- اختبار Offline ثم عودة الاتصال ثم تعارض جهازين.
- اختبار الحسابات الشخصية والغرف والصلاحيات وعدم تسرب البيانات.
- اختبار الإشعارات، المزامنة، الكاميرا، الميكروفون، النسخ الاحتياطي، والتصدير.
- اختبار RTL، لوحات المفاتيح العربية، التواريخ، العملات، والوضعين الفاتح والداكن.
- تشغيل Internal testing أولاً.
- إذا كان حساب المطور شخصياً جديداً بعد 13 نوفمبر 2023: اختبار مغلق مع 12 مختبراً على الأقل لمدة 14 يوماً متواصلة قبل طلب الوصول إلى Production.

### البوابة F: صفحة المتجر والمراجعة

- اختيار نوع حساب المطور الصحيح: شخصي أو مؤسسة. إذا تحول MYFI إلى خدمة مالية تجارية، نراجع ملاءمة حساب المؤسسة ومتطلبات التحقق.
- اسم التطبيق والوصف والصور والفيديو يصفون ما يقدمه التطبيق فعلاً دون وعود مالية مضللة.
- إكمال Content rating وTarget audience وAds declaration وApp access.
- توفير حساب تجريبي للمراجع إذا كانت بعض المسارات تحتاج تسجيل دخول، مع تعليمات لا تكشف بيانات مستخدم حقيقية.
- إضافة بريد دعم ورابط سياسة الخصوصية ورابط حذف الحساب عند انطباقه.
- مراجعة Pre-review checks في Play Console قبل الإرسال.

### البوابة G: الإطلاق والتشغيل

- إصدار أولي بنسبة صغيرة عبر staged rollout.
- تحديد `versionCode` و`versionName` وسجل تغييرات واضح.
- مراقبة الأعطال، ANR، المزامنة، الدخول، وفشل التصدير بعد الإطلاق.
- وجود قناة دعم وخطة استجابة للحوادث.
- وجود نسخة احتياطية قبل كل ترقية قاعدة بيانات أو تغيير مزامنة.
- إيقاف التوسع فور ظهور فقد بيانات أو تسرب خصوصية، مع خطة rollback واضحة.

## 3. تعريف الجاهزية

يصبح MYFI جاهزاً للنشر الرسمي فقط عند تحقق كل ما يلي:

```text
Product gate       = passed
Android gate       = passed
Signing gate       = passed
Privacy gate       = passed
Testing gate       = passed
Store gate         = passed
Operations gate    = passed
```

أي فشل في الخصوصية أو فقد البيانات أو التوقيع يمنع النشر حتى لو نجحت الواجهة.

## 4. ترتيب العمل في الخطة

1. تثبيت المنتج المالي والغرف والمزامنة.
2. إغلاق بوابتي المنتج وAndroid التقنية.
3. بناء سياسة الخصوصية وحذف الحساب وData safety.
4. إعداد Play Console والتوقيع والصفحة التجريبية.
5. Internal testing ثم Closed testing حسب نوع الحساب.
6. إصلاح نتائج الاختبار وإكمال App content والمراجعة المسبقة.
7. رفع `AAB` إلى Production بإطلاق تدريجي.
8. مراقبة أول إصدار ثم اعتماد دورة تحديث شهرية.
