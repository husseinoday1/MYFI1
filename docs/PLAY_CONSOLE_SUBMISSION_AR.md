# حزمة Play Console لإصدار MYFI

تاريخ التحضير: 2026-08-09

## بيانات التطبيق

- اسم التطبيق: MYFI
- نوع التطبيق: تطبيق إدارة مالية شخصية.
- الحزمة: `com.myfi.app`
- الإصدار الحالي: `1.0.0`
- رقم البناء الحالي: `1`
- نوع الحزمة المطلوبة للإنتاج: `AAB`
- قناة البداية المقترحة: Internal testing، ثم Closed testing، ثم Production staged rollout.

## وصف قصير مقترح

MYFI يساعدك على متابعة الرصيد، المصاريف، الديون، الأهداف، والالتزامات الشهرية بواجهة عربية واضحة.

## وصف كامل مقترح

MYFI تطبيق إدارة مالية شخصية يركز على وضوح الرصيد والحركات اليومية. يمكنك تسجيل الدخل والمصاريف والتحويلات بين المحافظ، متابعة الديون التي عليك أو لك، إنشاء أهداف ادخار، إدارة الالتزامات الشهرية، ومراجعة تقارير تساعدك على فهم أين تذهب أموالك.

يعمل MYFI محليًا أولًا، ويمكن تفعيل المزامنة الاختيارية عند الحاجة. الإدخال الذكي للصور أو الصوت يقترح تفاصيل الحركة قبل حفظها، ولا يسجل العملية تلقائيًا دون مراجعتك.

MYFI ليس بنكًا، ولا يقدم قروضًا، ولا استثمارًا، ولا تحويل عملات لحظي، ولا نصائح مالية ملزمة. هو دفتر مالي شخصي يساعدك على تنظيم بياناتك وفهمها.

## التصنيف والإفصاحات

- الفئة: Finance.
- يحتوي على إعلانات: لا.
- عمليات شراء داخل التطبيق: لا، إن لم تتم إضافة اشتراكات لاحقًا.
- خدمات مالية منظمة: لا.
- قروض شخصية أو ائتمان: لا.
- استثمار أو تداول: لا.
- خدمات مصرفية: لا.

في Financial features declaration اختر ما يطابق "personal finance / budgeting / expense tracking" فقط إن ظهر كخيار، ولا تختر قروضًا أو تداولًا أو خدمات مصرفية.

## Data safety draft

البيانات التي قد يعالجها التطبيق عند تفعيل الميزات:

- معلومات الحساب: البريد الإلكتروني عند تسجيل الدخول أو المزامنة.
- بيانات مالية: الحركات، المحافظ، الديون، الأهداف، الالتزامات، التصنيفات، التقارير.
- صور أو صوت: فقط عند استخدام تحليل الفاتورة أو التسجيل الصوتي.
- ملفات: عند استيراد أو تصدير نسخة احتياطية أو CSV/PDF.
- معرفات تقنية: معرف المستخدم أو الغرفة داخل Supabase عند تفعيل المزامنة.

الاستخدام:

- تشغيل التطبيق وتخزين البيانات المالية.
- المزامنة الاختيارية بين الأجهزة.
- النسخ الاحتياطي والاستعادة.
- تحليل فاتورة أو صوت عندما يطلب المستخدم ذلك.
- دعم المستخدم عند موافقته على إرسال تقرير تشخيصي.

المشاركة:

- لا تباع البيانات.
- لا تستخدم البيانات للإعلانات.
- قد تمر البيانات عبر Supabase وخدمات تحليل الصور أو الصوت عند تفعيل هذه الميزات.

الأمان:

- النقل عبر HTTPS.
- لا يوضع `service_role` داخل تطبيق العميل.
- النسخ الاحتياطية الحساسة يجب أن تكون اختيارية ومحميّة بكلمة مرور عند التصدير المشفر.

## الخصوصية وحذف الحساب

قبل النشر يجب توفير:

- رابط HTTPS عام لسياسة الخصوصية.
- نص سياسة خصوصية داخل التطبيق أو رابط واضح لها.
- مسار داخل التطبيق لطلب حذف الحساب إذا كان إنشاء الحساب متاحًا.
- رابط ويب خارجي لطلب حذف الحساب أو البيانات.
- شرح واضح لما يُحذف فورًا وما قد يُحتفظ به مؤقتًا لأسباب أمنية أو قانونية.

نص مختصر مقترح لطلب حذف الحساب:

```text
يمكنك طلب حذف حساب MYFI وبياناته المرتبطة عبر صفحة حذف الحساب أو من داخل الإعدادات. بعد تأكيد الطلب نحذف بيانات الحساب السحابية المرتبطة بالمستخدم، ولا نحذف النسخ الاحتياطية المحلية الموجودة على جهازك إلا إذا حذفتها أنت من الجهاز.
```

## متطلبات Android قبل الرفع

حسب متطلبات Google Play الحالية، ابتداءً من 31 أغسطس 2026 يجب أن تستهدف التطبيقات الجديدة والتحديثات Android 16، أي API 36 أو أعلى. تحقق من targetSdk في ملف AAB النهائي قبل الإرسال.

مصادر Google الرسمية:

- Target API: https://developer.android.com/google/play/requirements/target-sdk
- سياسة Target API: https://support.google.com/googleplay/android-developer/answer/16561298
- Data safety: https://support.google.com/googleplay/android-developer/answer/10787469
- User Data وPrivacy policy: https://support.google.com/googleplay/android-developer/answer/10144311
- حذف الحساب: https://support.google.com/googleplay/android-developer/answer/13327111
- Financial features declaration: https://support.google.com/googleplay/android-developer/answer/13849271

## ما لا أستطيع إغلاقه محليًا

- إنشاء حساب Play Console أو اختيار نوع المطور.
- رفع سياسة الخصوصية على رابط HTTPS عام.
- إنشاء رابط حذف الحساب الخارجي.
- تعبئة Data safety داخل Play Console.
- إنشاء Play App Signing أو مفاتيح الإنتاج.
- رفع AAB فعلي ومراجعة Pre-review checks.

## أمر البناء المقترح

```powershell
npm run build:aab
```

يعتمد هذا الأمر على `eas-cli` المثبت كاعتماد تطوير داخل المشروع. إذا طلب EAS تسجيل الدخول، شغّل:

```powershell
npx eas login
```

بعد نجاح البناء، ارفع الـ AAB إلى Internal testing أولًا ولا تبدأ Production قبل اختبار جهاز حقيقي ومراجعة الخصوصية وحذف الحساب.
