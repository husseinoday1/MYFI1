# MYFI

MYFI تطبيق مالي شخصي باللغة العربية، يساعد المستخدم على معرفة رصيده الحقيقي، ومتابعة دخله ومصروفاته والتزاماته وديونه وأهدافه المالية من خلال نموذج بيانات محلي واضح.

## الحالة الحالية

المشروع تطبيق Expo/React Native قيد التطوير. يعمل محليًا أولًا، مع مزامنة Supabase اختيارية. النموذج المالي الأساسي موجود، بينما ما زالت ميزة الغرف والمشاركة الانتقائية في مرحلة التصميم والتنفيذ المرحلي.

## مبادئ المنتج

- الحسابات المالية أهم من شكل الواجهة.
- كل حركة مالية تمر عبر مصدر بيانات موحد.
- التحويل بين المحافظ ليس دخلًا ولا مصروفًا.
- الإدخال الذكي اقتراح قابل للمراجعة، وليس حفظًا تلقائيًا.
- الالتزام يقاس بدورة شهرية، ويمكن تأجيل تنفيذه إلى تاريخ يومي.
- الدفع المرتبط بدين أو هدف أو التزام لا يتكرر في التقارير.
- البيانات الشخصية خاصة افتراضيًا.
- المشاركة في الغرف لا تتم إلا بإذن صريح وبصلاحية محددة.

## المزايا الرئيسية

- محافظ وحسابات متعددة.
- دخل ومصروف وتحويلات وتسويات.
- ديون مستحقة للآخرين أو مستحقة للمستخدم.
- أهداف ادخار مع مبالغ محجوزة.
- التزامات شهرية مع تأجيل يومي.
- معاملات متكررة شهريًا مع مراجعة قبل الإنشاء.
- إدخال سريع واقتراحات تصنيف محلية.
- تقارير وتوقعات ونسخ احتياطي واستعادة.
- مزامنة اختيارية مع Supabase.
- تصميم RTL عربي ودعم Android وiOS والويب عبر Expo.

## التشغيل المحلي

المتطلبات:

- Node.js LTS.
- npm.
- Expo CLI المضمنة مع المشروع.
- Android Studio عند الحاجة إلى تشغيل النسخة الأصلية على Android.

تثبيت الاعتمادات:

```powershell
npm install
Copy-Item .env.example .env
```

شغّل التطبيق:

```powershell
npm start
```

ثم افتحه عبر Expo Go أو شغّل نسخة Android محلية:

```powershell
npm run android
```

لا تضع مفاتيح حقيقية في المستودع. عدّل `.env` محليًا فقط، واترك `.env.example` كمرجع للإعدادات المطلوبة.

## الإعدادات البيئية

يستخدم المشروع المتغيرات التالية عند تفعيل Supabase:

- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_KEY`
- `EXPO_PUBLIC_NORMALIZED_READ_MODE`
- `EXPO_PUBLIC_OCR_URL`
- `EXPO_PUBLIC_TRANSCRIBE_URL`

يجب أن يكون المفتاح المستخدم في تطبيق العميل مفتاحًا عامًا مخصصًا للعميل. لا تضع `service_role` أو أي مفتاح سري داخل `.env` الذي يرفع إلى Git.


## الملفات المؤقتة

كل نواتج التصدير المحلية، سجلات Expo، تقارير الفحص، أرشيفات أدوات Supabase، والنسخ التجريبية تجمع داخل `tmp/` أو تحذف مباشرة. المجلد موجود للعمل المحلي فقط ومضاف إلى `.gitignore`.

بعد انتهاء الحاجة إليها يمكن تنظيفه من PowerShell:

```powershell
Remove-Item -LiteralPath .\tmp -Recurse -Force
```

سيعاد إنشاء المجلد عند الحاجة، ولن يؤثر حذفه على التطبيق أو بيانات المستخدم.

## سياسة الرفع إلى المستودع

يرفع Git فقط الشيفرة والمخططات والاختبارات والأصول المطلوبة للتطبيق والتوثيق. لا ترفع:

- `.env` أو أي مفتاح أو شهادة أو ملف اعتماد.
- `node_modules` و`.expo` ومخازن الحزم.
- ملفات البناء والتصدير وملفات APK/AAB.
- سجلات التشغيل وبيانات التطبيق الشخصية وقواعد البيانات المحلية.
- أدوات Supabase التنفيذية والأرشيفات المحلية.
- أي ملف داخل `tmp/`.

قبل إنشاء commit:

```powershell
git status --short
git diff --check
```

## خارطة الطريق

1. تثبيت Financial Engine ومصدر الحسابات الموحد.
2. استكمال الالتزامات الشهرية والتكرار الشهري وربط الدفعات.
3. تحسين التقارير والتوقعات والنسخ والاستعادة والمزامنة.
4. تنفيذ الغرف: الدعوات بالبريد، الأدوار، المشاركة الانتقائية، الإسقاط الآمن، والإلغاء.
5. إضافة الذكاء الاصطناعي والميزات التجارية بعد ثبات النموذج المالي.
6. تجهيز الإصدار الرسمي على Android وفق بوابات المنتج، الأمان، الخصوصية، الاختبار، Play Console، والمراقبة.
7. بناء دليل مستخدم كامل ومركز دعم داخل الإعدادات لتوثيق المفاهيم، خطوات الاستخدام، استقبال المشاكل، وربط البلاغات بالإصلاحات.
